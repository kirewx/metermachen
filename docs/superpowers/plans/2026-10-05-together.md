# Together Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gemeinsame Aktivitäten von Mitgliedern erkennen (Strava-Route + Zeit oder manuelles Taggen), bestätigen lassen und in Feed, Profil und Achievements zeigen; vorher die Strava-Sync-Grundlage (Ignore-Liste, Update/Delete-Webhooks, Track-Erfassung) bauen.

**Architecture:** PR 1 erweitert `services/strava.py` um Update/Delete-Webhooks, eine Ignore-Liste und eine `ActivityTrack`-Tabelle (Geo-Daten dauerhaft, inkl. `private`-Flag); ein gemeinsamer Lösch-Helfer ersetzt die verstreuten Löschpfade. PR 2 fügt reine Geo-Funktionen (`together_geo.py`), den Session-Service (`together.py`), einen Router und vier Achievements hinzu, alles hinter dem Add-on `together`. PR 3 baut die React-Komponenten in `components/together/`.

**Tech Stack:** FastAPI, SQLModel/SQLite, pytest (Backend, `uv`); React, TanStack Query, Vitest (Frontend).

**Spec:** `docs/superpowers/specs/2026-10-05-together-design.md`

## Global Constraints

- Neue technische Bezeichner durchgehend englisch; UI-Texte deutsch.
- Keine neuen Python-Abhängigkeiten (Polyline-Decoder selbst geschrieben).
- Geo-Daten (`start_lat/lng`, `end_lat/lng`, `polyline`) werden dauerhaft und ungekürzt gespeichert, auch für „Nur ich“-Aktivitäten (`private=True`); gelöscht nur mit der Aktivität bzw. beim Strava-Disconnect.
- Schwellen: Auto `share ≥ 0.5 and km ≥ 2.0`; Vorschlag `share ≥ 0.3 or km ≥ 2.0`; Radius 50 m; Zeitüberlappung `≥ 600 s or ≥ 50 %` der kürzeren Aktivität; Vorschlags-Ablauf 14 Tage; Tag-Auswahl Datum ±1 Tag.
- Matching-Fehler werden geloggt und brechen nie einen Import oder Request.
- Keine lokalen Pfade (Home-Verzeichnisse, `~/.claude`) in Repo-Dateien.
- Backend-Tests: `cd backend && uv run pytest`; Frontend-Tests: `cd frontend && NODE_OPTIONS=--no-experimental-webstorage npm test`.
- Neue Datetimes aus SQLite sind naiv → als UTC interpretieren (Muster `deps._as_utc`).

## Review Focus

- Eine manuelle (nicht Strava-)Aktivität löschen darf keinen `StravaIgnored`-Eintrag erzeugen; Strava-Disconnect ebenfalls nicht. → Tests in Task 1.
- Zwei eigene, zeitgleiche Aktivitäten (Uhr + Handy) dürfen nie miteinander matchen. → Test in Task 7.
- Eine „Nur ich“-Aktivität wird importiert, mit `private=True` gespeichert und trotzdem gematcht; ein späteres Umschalten der Sichtbarkeit bei Strava aktualisiert `private`, auch wenn die Aktivität in MeterMachen bearbeitet wurde. → Tests in Task 2, 3 und 7.
- Matching mehrfach für dieselbe Aktivität (Update-Webhooks) erzeugt keine doppelten Sessions/Teilnahmen und hebt bestehende `confirmed` nicht auf. → Test in Task 7.
- Deaktivierte Nutzer (`is_active=False`) werden weder gematcht noch sind sie taggbar. → Tests in Task 7 und Task 9.

### Task 5: Geo-Funktionen

**Files:**
- Create: `backend/app/services/together_geo.py`
- Test: `backend/tests/test_together_geo.py`

**Interfaces:**
- Produces:
  - `decode_polyline(encoded: str) -> list[tuple[float, float]]` (Google-Format, Präzision 5; wirft `ValueError` bei kaputtem String)
  - `time_overlap_s(start_a: datetime, elapsed_a: int, start_b: datetime, elapsed_b: int) -> float`
  - `times_overlap(start_a, elapsed_a, start_b, elapsed_b) -> bool` — `overlap ≥ 600` oder `overlap ≥ 0.5 * min(elapsed_a, elapsed_b)` (bei `min == 0` nur die 600-s-Regel)
  - `covered_km(a: list[tuple[float, float]], b: list[tuple[float, float]], radius_m: float = 50.0) -> float`
  - `route_overlap(a: list[...], b: list[...], dist_a_km: float, dist_b_km: float) -> tuple[float, float]` → `(km_together, share)` mit `km_together = min(covered_km(a, b), covered_km(b, a))`, `share = km_together / min(dist_a_km, dist_b_km)` (0, wenn min 0)

`covered_km`: für jedes Segment `(p, q)` von A den Mittelpunkt `m` nehmen; abgedeckt, wenn die minimale Distanz von `m` zu einem Segment von B ≤ `radius_m`. Distanz: lokale equirektangulare Projektion um `m` (`x = Δlng·cos(lat_m)·R`, `y = Δlat·R`, `R = 6371000`), dann klassische Punkt-zu-Segment-Projektion mit Klemmung auf `[0, 1]`. Summe der Haversine-Längen abgedeckter Segmente in km. B mit < 2 Punkten → 0.
